# 보안

OWASP Top 10 · ASVS 요점과 일반적인 백엔드 보안 관례를 따른다.

## 인증·인가

- 기본적으로 인증이 필요하다. 공개 경로는 허용 목록으로만 연다.
- 토큰은 서명·만료를 검증한다. 비밀번호·개인정보를 토큰에 넣지 않는다.
- 인가: “로그인했는가”뿐 아니라 **그 리소스에 접근할 수 있는가**(소유자·테넌트)를 확인한다.

## 입력

- 모든 외부 입력은 서버에서 검증한다.
- SQL·쿼리에 사용자 입력을 문자열로 이어 붙이지 않는다 (prepared statement / 바인딩 사용).
- 파일 업로드는 확장자·크기·Content-Type을 제한하고, 저장 파일명은 서버가 정한다.
- 사용자가 준 URL로 서버가 임의 호출하지 않는다 (SSRF).

## 비밀

- 비밀은 코드·설정 파일·이미지에 넣지 않는다. 환경 변수·비밀 저장소를 쓴다 ([config](../config/README.md)).
- 로그·에러 응답에 비밀이 나가지 않게 한다 ([logging](../logging/README.md), [response](../response/README.md)).

## 전송·암호

- 운영 구간은 TLS. 인증서 검증을 끄지 않는다.
- 비밀번호 저장은 bcrypt / Argon2 등 검증된 KDF. 자체 해시 설계를 하지 않는다.

## 의존성

- 새 라이브러리는 필요성·라이선스·알려진 취약점을 확인한다.
- 버전은 고정한다 (`latest` 금지).
