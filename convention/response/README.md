# 응답 · 에러

REST API에서 흔히 쓰는 성공/실패 응답 관례를 따른다.

## 성공

- 조회·처리 성공: `200 OK` + 본문
- 생성 성공: `201 Created` (+ `Location` 헤더 권장)
- 본문 없는 성공: `204 No Content` (삭제 등)

본문 형태는 프로젝트에서 하나로 통일한다. 예:

```json
{
  "data": { }
}
```

또는 리소스 객체를 최상위에 바로 둔다. **한 가지를 정하면 섞지 않는다.**

## 실패

- 클라이언트 잘못: `4xx`
- 서버 잘못: `5xx`
- 검증 실패: `400` 또는 `422`
- 인증 필요: `401`
- 권한 없음: `403`
- 없음: `404`
- 충돌(중복 등): `409`

에러 본문도 형식을 통일한다. 예:

```json
{
  "code": "ORDER_NOT_FOUND",
  "message": "주문을 찾을 수 없습니다."
}
```

- `code`는 기계가 처리하는 안정적인 식별자 (UPPER_SNAKE)
- `message`는 사람이 읽는 설명. 내부 스택·SQL을 노출하지 않는다.

## 처리

- 컨트롤러/서비스에서 던진 업무 예외는 `@RestControllerAdvice`에서 공통 변환한다.
- 예상 못 한 예외는 `500` + 일반적인 메시지. 상세는 로그만.
